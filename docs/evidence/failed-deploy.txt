command line with a tag that does not exist in the registry, to see what a
failed deploy does to a running app. Copied from the terminal at the time,
because the failed revision has since been deactivated and no longer appears

Two things came out of this. The app stayed up, because Container Apps does
not move traffic to a revision that never becomes healthy. And the apply
reported success: ARM accepted the configuration, so provisioningState is
Provisioned, while the runtime failed separately afterwards. A green apply is
not evidence that the new image is running, which is why the deploy workflow
checks the revision's running state before it finishes.

The 5xx alert did not fire, correctly. No user-visible error happened.
